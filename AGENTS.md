# Working on EVA future demos

Owner-approved scope: the entire fictional text-to-world experience, built incrementally in one application. This workspace's rules replace the old project's mandatory workflows. The current request determines the increment; the roadmap is not an instruction to implement everything.

## Do the task, not the ceremony

- Read the short PLANNING.md, then only affected implementation, callers and relevant tests. Search specific paths. Do not scan docs/archive, Git history, other projects or old datasets unless asked or an actual dependency requires it.
- Implement exactly the requested task. Reuse first; choose the smallest complete change. No unsolicited features, research, refactoring, generalization or future scaffolding.
- Desktop/exhibition is the target. Do not create a mobile prototype, responsive variant or touch pass unless requested. Preserve existing keyboard access, readable controls and focus behavior.
- Work directly for routine tasks. No mandatory brainstorm, spec, implementation-plan document, swarm, routing exercise, delegation or independent review. Ask one focused question only when a material ambiguity blocks the task. Use specialists when requested or genuinely useful.
- Figma/Weave generation is optional, not a prerequisite for UI edits. Use it when requested or propose it when it would help; paid generation still needs finite approval. Historical visual packets are references, not active gates.
- Verify the affected behavior. For visual work, run available build/type checks and inspect the relevant desktop state. For new non-trivial logic, add or update a focused test. For docs, check the diff and active links. Do not run unrelated full-project acceptance suites.
- Security review is relevant to changes involving credentials, permissions, uploads, external execution or similar boundaries; it is not a ritual for visual-only changes. Preserve protections already in affected code.
- No mandatory phase paperwork or acceptance packets for routine work. Stop at the requested increment. Public demonstration and deployment remain explicit owner decisions.

## Be accurate and preserve the work

- Distinguish existing behavior, proposals, fixtures and actual live generation. Never claim an unrun check passed, an unavailable integration works, or an agent/model participated without evidence.
- Preserve concurrent edits, originals and historical records. Inspect exact targets before destructive changes. No blanket cleanup, silent overwrites or deletion of the old checkout.
- No automatic commits, pushes, publishing, installations, model downloads, spending, credential access or permission bypass. Use authorized existing tools; ask for specific additional actions when needed.
- Models may propose data, not executable code or permission. Keep operational facts, contribution history and stop controls truthful even when EVA is unreliable within the fiction.
- End with a concise summary of changed files, actual checks and material limitations. Do not invent an obligatory next phase.

Historical documents are retained for the owner, not active instructions. The original implementation plan's mandatory Weave passes, retained old routes, Week 4 paths and phase gates are superseded here; consult individual technical ideas only when needed.
